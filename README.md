Готовые примеры работы с **API проверки ссылки** на шести языках: **Python, TypeScript (Node.js), Go, Java, C#, PHP.**
Узнать, отмечен ли адрес как **фишинговый**, раздающий **вредоносное ПО** или **нежелательное ПО** — по одной ссылке или пакетом до 100 адресов за вызов.

Каждый пример **запускается сразу — без регистрации, без ключа, без карты.** В коде зашит публичный демо-ключ.

```bash
git clone https://github.com/atlorium-api/url-reputation-api-client
cd url-reputation-api-client/python && pip install -r requirements.txt && python main.py
```

> Демо-ключ отвечает **моками**, а не реальными данными репутационной базы. Ветку ответа задаёт домен из зарезервированной под примеры зоны `example.com` — поэтому обе содержательные ветки, «чисто» и «угроза», воспроизводятся в тесте, а не выпадают случайно. Подставьте боевой ключ — тот же код начнёт возвращать настоящие вердикты.

## Зачем это нужно

Модерация ссылок в объявлениях, комментариях и чатах. Проверка адресов из входящей почты до того, как по ним кликнут. Фильтрация ссылок в пользовательских профилях и подписях. Аудит внешних ссылок на своём сайте.

Ключевое: вердикт приходит **машиночитаемым JSON — до перехода по ссылке**. Сервис не загружает проверяемую страницу и не открывает к ней соединений, поэтому проверка не «предупреждает» владельца опасного сайта о том, что его смотрят.

Примеры не просто печатают JSON, а **применяют данные**: в каждом есть функция `screenUserContent()`, которая по вердиктам всех ссылок публикации решает её судьбу — опубликовать, отправить модератору или отклонить. Правила разные для разных категорий: фишинг и вредонос блокируют публикацию сразу, нежелательное ПО уходит человеку, а строка без вердикта **не считается безопасной** и тоже уходит человеку.

## Быстрый старт за 60 секунд

Проверить API вообще без клонирования:

```bash
curl -H "Authorization: Bearer ak_sandbox_demo_mockdata_v1" \
     "https://atlorium.com/api/urlcheck?url=https://phishing.example.com/login"
```

### Домены-сценарии в песочнице

Демо-ключ выбирает ветку ответа по домену проверяемого адреса. Сравнение идёт по окончанию имени, поэтому работают и поддомены.

| Адрес | Что вернёт |
|-------|------------|
| `malware.example.com` | `threat`, категория `malware` |
| `phishing.example.com` | `threat`, категория `social_engineering` |
| `unwanted.example.com` | `threat`, категория `unwanted_software` |
| `danger.example.com` | `threat`, **две категории сразу** — проверьте, что ваш разбор читает весь список, а не первый элемент |
| любой другой | `clean` |

## Аутентификация

Ключ передаётся в заголовке `Authorization`:

```
Authorization: Bearer ВАШ_КЛЮЧ
```

| Ключ | Что делает |
|------|------------|
| `ak_sandbox_demo_mockdata_v1` | **Демо-ключ.** Публичный, один на всех. Возвращает моки, денег не списывает, регистрации не требует. Ответы детерминированы — на них можно писать стабильные тесты. |
| Боевой ключ | Настоящие вердикты репутационной базы. Получить в личном кабинете: [atlorium.com](https://atlorium.com) |

Переход на боевой ключ **не требует правок в коде** — все примеры читают переменную окружения:

```bash
export ATLORIUM_API_KEY="ak_ваш_боевой_ключ"
```

Каждый ответ песочницы помечен заголовком `X-Atlorium-Sandbox: true` — перепутать мок с реальным вердиктом невозможно.

## Эндпоинты

Базовый адрес: `https://atlorium.com`

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET` | `/api/urlcheck` | Вердикт по одной ссылке |
| `POST` | `/api/urlcheck/batch` | Пакет ссылок за один вызов |

### `GET /api/urlcheck`

| Параметр | Где | Тип | Описание |
|----------|-----|-----|----------|
| `url` | query | string | Проверяемый адрес. Схему можно опустить: `example.com/page` будет приведено к `http://example.com/page`. Принимаются только `http` и `https`. В ответе адрес возвращается в приведённом виде — именно в нём он и проверялся |

### `POST /api/urlcheck/batch`

Тело запроса — массив строк:

```json
[ "https://example.com", "http://phishing.example.com/login" ]
```

| Параметр | Где | Тип | Описание |
|----------|-----|-----|----------|
| — | тело | string[] | Список адресов, максимум **100**. Пустые строки и повторы отбрасываются до проверки: повтор не добавляет работы и не оплачивается |

Порядок результатов совпадает с порядком присланных ссылок — сопоставляйте по индексу.

## Поля ответа

### Вердикт по ссылке

| Поле | Тип | Что содержит |
|------|-----|--------------|
| `url` | string | Адрес в приведённом виде — тот, в котором он проверялся |
| `verdict` | string | **Ключевое поле.** `clean` — отметок нет, `threat` — угроза, `unknown` — вердикт получить не удалось |
| `threatTypes` | array | Категории угрозы: `malware`, `social_engineering`, `unwanted_software`. **Это список** — один адрес может быть отмечен сразу по нескольким |
| `checkedAtUtc` | datetime | Момент проверки. Показывайте его рядом с вердиктом: он превращает утверждение в датированное |
| `message` | string | Пояснение для человека |
| `elapsedMs` | number | Длительность проверки, мс |

### Пакетный ответ

| Поле | Тип | Что содержит |
|------|-----|--------------|
| `results` | array | Вердикты в порядке присланных ссылок |
| `total` | number | Сколько ссылок проверено |
| `threatCount` | number | Сколько отмечено как опасные |
| `unknownCount` | number | Сколько осталось без вердикта. **Эти строки не тарифицируются** |
| `elapsedMs` | number | Длительность всей проверки, мс |

## Что означает «чисто» — и чего сервис не делает

Это главная оговорка, и её лучше прочитать до интеграции, а не после.

**`clean` означает «на момент проверки в базе нет отметки об угрозе», а НЕ «сайт безопасен».** Свежий фишинговый домен попадает в любую репутационную базу мира не мгновенно, а за часы: сначала на него должны пожаловаться или его должна обойти автоматика. Поэтому в каждом ответе есть `checkedAtUtc` — показывайте его рядом с вердиктом. В примерах на этом построена отдельная ветка: вердикт «чисто» старше суток помечается как требующий перепроверки перед долгой публикацией.

**Сервис не загружает проверяемую страницу**, не резолвит её имя и не открывает к ней соединений. Отсюда и плюс, и ограничение: проверка незаметна для владельца опасного сайта, но ничего не говорит о содержимом страницы — только о наличии отметки в базе.

## Обработка ошибок

| Код | Причина | Что делать |
|-----|---------|------------|
| `400` | Ссылка не указана или не распознана | Нужен адрес `http`/`https`. В пакете: список пуст, содержит только негодные адреса или длиннее 100 строк |
| `401` | Ключ отсутствует, просрочен или недействителен | Проверьте заголовок `Authorization` |
| `402` | Недостаточно кредитов на балансе | Пополнить на [atlorium.com](https://atlorium.com) |
| `429` | Превышен rate-limit | Повторить с задержкой. **Ставьте потолок ожидания** — сервер может честно попросить подождать десятки минут |
| `503` | Вердикт получить не удалось | Повторить позже. **За сбой на нашей стороне деньги не списываются** |

Во всех шести примерах коды разложены в человекочитаемые причины — смотрите класс `AtloriumError`.

## Цены и лимиты

Оплата **pay-as-you-go, без подписки**. Одна ссылка — одна единица работы; в пакете единиц столько, сколько ссылок. Строки без вердикта (`verdict = unknown`) из списания **вычитаются**: если по трём строкам из ста вердикт получить не удалось, спишется девяносто семь единиц, а не сто. Запрос, в котором не проверилась ни одна ссылка, не тарифицируется вовсе.

## Частые вопросы

**Можно ли по вердикту `clean` гарантировать пользователю, что сайт безопасен?** Нет, и обещать этого не стоит. `clean` — это «отметки нет на момент проверки». Показывайте рядом `checkedAtUtc`.

**Чем это отличается от предупреждения браузера?** Это тот же класс проверки, но в машиночитаемом виде и **до** перехода: вы получаете вердикт на сервере и решаете судьбу ссылки сами, а не после того, как посетитель уже кликнул.

**Проверяет ли сервис содержимое страницы?** Нет. Страница не загружается вовсе — проверяется только наличие отметки об адресе в репутационной базе.

**Сколько ссылок можно послать пакетом?** До 100 за вызов. Ограничение не техническое, а ради предсказуемости: сотня укладывается в секунды, и вы получаете ответ, а не таймаут своего HTTP-клиента на середине.

**Что делать с `verdict: unknown`?** Трактовать как «не проверено», а не как «безопасно». Такие строки не тарифицируются, и в примерах они уходят на ручную модерацию.

**Работают ли ссылки с параметрами и якорями?** Да, адрес проверяется целиком в приведённом виде. Он же возвращается в поле `url`.
